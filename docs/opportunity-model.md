# Opportunity Model

This document describes how validated Trends become scored Opportunities for a
Persona, the lifecycle states an Opportunity passes through, and how the
AI Engineering Radar displays them.

## Trend to Opportunity workflow

1. The Trend Detector clusters `Signals` into `Trends` and marks those with
   enough persistence as `Active`.
2. The Opportunity Analyst (`ode.opportunities`) reads all `Active` trends for
   the requested Persona.
3. Each Active Trend is scored using the five-component Opportunity Score.
4. If the score is above the threshold (`SCORE_THRESHOLD = 60.0`) the required
   questions can be answered, an `Opportunity` is persisted.
5. Re-running the analyst updates existing opportunities for the same
   `(trend_id, persona_id)` pair instead of creating duplicates.

## Scoring model

The Opportunity Score is a deterministic number from 0 to 100.

| Component        | Weight | Formula (simplified)                                |
|------------------|--------|-----------------------------------------------------|
| Evidence Quality | 0–35   | `min(35, evidence_quality / 100 * 35)`             |
| Momentum         | 0–30   | `min(30, abs(trend.momentum) * 0.30)`              |
| Adoption         | 0–15   | `min(15, signal_volume / 50 * 15)`                 |
| Growth           | 0–10   | `min(10, abs(momentum) / days_in_trend * 10)`      |
| Relevance        | 0–10   | `min(10, intent_match_score(entity, summary, intent) * 0.5)` |

The total is the sum of the components.  Scores are reproducible when run
against the same Signals and intent.

Persona Fit is intentionally excluded from the scoring model. Without explicit
user-profile data, persona matching adds noise and can make strong
recommendations look arbitrary.

## Opportunity lifecycle

Opportunities start in the `Emerging` state when first created.  Later lifecycle
states are defined as the product matures:

- `Emerging` — newly created
- `Validated` — confirmed by further signals or user interaction
- `Growing` — consistently gaining momentum
- `Mature` — plateaued at high activity
- `Declining` — losing momentum
- `Expired` — outside `valid_until` window

For the MVP the lifecycle is initialised to `Emerging` and updated on re-scoring.

## LLM explanation

The score is computed purely from data.  Explanations are generated by
`ode.llm.generate_explanation`, which is an extension point for an LLM (Ollama
preferred, Llama3 fallback).  When no LLM backend is configured, a
deterministic template is used.  Explanations cover:

- Why the opportunity matters now
- Who benefits
- What action to take
- Supporting evidence from the score components

## Radar relationship

The AI Engineering Radar page (`app/pages/ai_engineering_radar.py`) lists all
Opportunities for the Engineer persona, sorted by `score DESC`.  Each item shows
its title, total score, component breakdown, lifecycle status, recommendation,
and expandable explanation.
